Documentação da API

Autenticação e Identificação do Tenant

Para consumir esta API, é necessário obter uma apiKey e um tenant, que serão fornecidos pela associação. Ambos são obrigatórios e devem ser incluídos no cabeçalho da requisição.

  • X-Tenant-ID: Representa o identificador do tenant.
  • Authorization: Deve conter a apiKey fornecida.

Limites de Uso da API

Para garantir a estabilidade e o desempenho da API, aplicamos limites de requisição. Atualmente, o limite é de:

  • 1 requisição por segundo por chave de API.

Caso o limite seja ultrapassado, a API poderá responder com um erro 429 Too Many Requests.

3. Obter Eventos

Obtenção de eventos de uma organização..

GET /organizacoes/{id}/eventos

Filtros Disponíveis

A consulta permite o uso de diversos filtros opcionais para refinar os resultados. Caso um filtro não seja fornecido, ele será ignorado na busca.

  • IdOrganizacao (GUID): Filtra pelo identificador da organização.
  • IdEsteira (GUID): Filtra pelo identificador da esteira.
  • IdEtapa (GUID): Filtra pelo identificador da etapa.
  • TipoDeEvento (GUID): Filtra pelo tipo de evento.
  • Status (GUID): Filtra pelo status do evento.
  • Tenant (string): Identificador do tenant.
  • Protocolo (string): Filtra pelo número do protocolo.
  • Sla (string): Filtra pelo SLA associado ao evento.
  • Situacao (string): Filtra pela situação do evento.
  • Nome (string): Filtra pelo nome do usuário.
  • Documento (string): Filtra pelo número do documento.
  • Placa (string): Filtra pela placa do veículo.
  • Chassi (string): Filtra pelo número do chassi.
  • Renavam (string): Filtra pelo número do Renavam.
  • Inicio (DateTime): Data inicial da busca.
  • Fim (DateTime): Data final da busca.
  • Cep (string): Filtra pelo CEP.
  • Logradouro (string): Filtra pelo logradouro.
  • Bairro (string): Filtra pelo bairro.
  • Cidade (string): Filtra pela cidade.
  • Estado (string): Filtra pelo estado.
  • Skip (int): Número de registros a serem ignorados.
  • Take (int): Número máximo de registros a serem retornados.

Os filtros skip e take são usados para paginação e devem ser configurados corretamente para evitar erros.

Filtros Obrigatórios

A consulta requer alguns filtros obrigatórios que devem ser passados corretamente para evitar erros na requisição.

  • skip: Deve ser menor do que o valor de take.
  • take: Deve ser menor do que o valor de take.
  • início: Campo obrigatório. Deve representar o início do intervalo de consulta e deve ser menor ou igual ao campo fim.
  • fim: Campo obrigatório. Deve representar o fim do intervalo de consulta e deve ser maior ou igual ao campo início.

Caso esses critérios não sejam atendidos, a API retornará um erro 400 Bad Request com a respectiva mensagem de validação.

Exemplo de Requisição

curl --location 'https://api.gestaosegura.app/bi/organizacoes/769fd020-09ae-4e7d-b4ad-fd1f63a5fcb7/eventos?skip=0&take=10&inicio=2025-02-01&fim=2025-03-01' \
--header 'X-Tenant-ID: de87a4c4-6a00-4a38-9896-5b5b61a00d1c' \
--header 'Authorization: teste'
